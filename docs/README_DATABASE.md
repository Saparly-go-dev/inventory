# База данных

Приложение рассчитано на **PostgreSQL** как основную БД.

Дополнительно в конфиге присутствует секция **MySQL** — она используется для синхронизации сотрудников (`POST /api/employees/sync`). Если MySQL не нужен — этот функционал не используйте.

> Важно: не храните реальные пароли в репозитории. Везде ниже используйте значения‑заглушки и задавайте секреты через `.env`/секрет‑хранилище.

## PostgreSQL (обязательно)

### Параметры подключения

Файл: `configs/config.yaml` (секция `db`):

- `db.host` — адрес PostgreSQL (например, `127.0.0.1`)
- `db.port` — порт (обычно `5432`)
- `db.username` — пользователь (например, `postgres`)
- `db.dbname` — база (например, `inventory`)
- `db.sslmode` — режим SSL (например, `disable` для локальной разработки)

Пароль пользователя задаётся через `.env`:

- `.env`: `DB_PASSWORD=...`

### Создание пользователя и базы (пример)

Подключитесь к PostgreSQL под админом и выполните:

```sql
CREATE ROLE postgres WITH LOGIN PASSWORD 'CHANGE_ME' SUPERUSER;
CREATE DATABASE inventory OWNER postgres;
```

Если роль/БД уже существуют — достаточно обновить пароль:

```sql
ALTER ROLE postgres WITH PASSWORD 'CHANGE_ME';
```

### Миграции

Бэкенд сам выполняет `AutoMigrate` при старте (таблицы создаются/обновляются автоматически).

## MySQL (опционально)

Используется как источник данных для синхронизации сотрудников.

Параметры подключения находятся в `configs/config.yaml` (секция `mysql`):

- `mysql.host`
- `mysql.port`
- `mysql.username`
- `mysql.password`
- `mysql.dbname`

Если вы планируете использовать синхронизацию:

- Убедитесь, что MySQL доступен с сервера, где крутится бэкенд.
- Проверьте, что таблица‑источник существует (в коде используется `Info_info_employee`).
